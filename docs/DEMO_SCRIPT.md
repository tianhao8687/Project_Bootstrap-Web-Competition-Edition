# 90-Second Competition Demo

## Before recording

- Use a 1440px-wide browser.
- Select Demo Data for a deterministic stage walkthrough, or preflight valid live credentials and GitHub limits.
- Start from a cleared local session.

## Script

**0-15 seconds — Start**

Enter: “Build a client-deliverable checker for freelance designers, with reminders, file organization, and client history.” Explain that AI coding often fails because the direction is still vague, not because code is hard.

**15-30 seconds — BRIEF**

Show the focused target user, MVP, non-goals, and confirmation gate. Explain that only questions that change the executable outcome should interrupt the user. Confirm BRIEF.

**30-55 seconds — Open-source reality check**

Point to the verdict and limitation at the top, then show related repositories, detected license state, balanced advantage/weakness columns, and expandable evidence. Explain that README claims remain author claims and repository content cannot issue instructions.

**55-70 seconds — User-authorized change**

Select “Narrow the MVP to one demonstrable primary flow.” Point to its `PROJECT_BRIEF.md` impact badge and the pending-change summary. Click Apply and Continue; nothing else is written back.

**70-85 seconds — PLAN and RULES**

Confirm PLAN, then show the generated RULES. Explain that later AI receives scope, implementation, and execution permissions as separate files and cannot silently change confirmed direction.

**85-90 seconds — Handoff**

Show copy, individual download, and Download All ZIP. Close with: “One idea, one reality check, three executable files.”

## Honest limitation line

“This demo uses labeled deterministic data; live mode calls a configured model and GitHub, where rate limits and model variation are shown as recoverable limitations instead of hidden.”
